# 工程决策

2026-11-07，基于 `79cddf2` 克隆的实际仓库，本地任务分支 `codex/mirror-moon`。未推送远端、未创建 PR。

- 保留现有小模块边界：`domain/tracking/interaction/transport/pipeline/render/app/diagnostics`。Gemini 的任务卡提供验收意图，不要求把现有文件重建成另一套包目录。
- Python 3.12.15；实际 wheel 为 MediaPipe 1.2.2、OpenCV contrib 5.0.0.93、PySide6 6.12.0、ModernGL 5.13.0、NumPy 2.5.4。导入与模型实测后冻结锁文件。只安装一个 OpenCV 提供者。
- 采集容量一，Hands/Pose 同帧同 VIDEO 时间戳；渲染读取该快照自己的图像。瞬时事件使用单消费者原子消费、有界序号队列，重复 ID 无效，积压溢出停止并记录错误，过时事件显式计数。
- `perf_counter()` 是本工程的高分辨率单调时钟。避免 Windows 上粗分辨率计时把每帧耗时量化成 0ms；不使用墙上时间作动作判断。
- 跨模型只比较像素坐标；手部 handedness 仅加很小权重。Pose 双腕重叠或两种关联成本近似时输出 UNKNOWN。已有施法的解剖角色保持锁定，可靠 Pose 腕可标记 POSE_FALLBACK；没有手形观测不推测开掌/握拳。
- 强度来自 Pose world 的三维肘内角、个人端点和骨段稳定性。掌宽变化不等同完全伸直，2D 前臂长度也不替代深度。
- 握臂转移优先于普通离胸取消，但须有已有 CAST、近期朝前臂接近的证据与时限。接近趋势按秒的短窗估计；图形测试发现按每帧距离差会随跟踪频率变化，已修正。
- 碎镜必须由真实可见的快速收缩与最小间距共同确认。最多保留 150ms 的已观测收缩轨迹供重新看见手后继续验证；丢手期间不外推、不产生碎镜事件。短失手保持，长失手关闭。
- Qt 默认 FBO 每帧读取，ID/物理尺寸变化时重新 detect，Qt 拥有的 FBO 不由应用删除。GL 对象只在主线程当前上下文创建/释放。10 次缩放/全屏以非对称色标检查方向与比例。
- 标准/高画质：只从特效输出生成半分辨率横/纵模糊 Bloom；轻量关 Bloom。QPainter 为唯一兼容回退；其中折镜为简化画质，不作为高阶视觉达标证据。
- 碎片使用触发事件所携带的不可变摄像头帧，网格 UV 保留原图内容，不随较新快照覆盖。活动碎镜/斩击与缓存均有上限。
- 关闭先请求停止并在 Qt 事件循环中短轮询，确认采集和模型线程退出后才销毁窗口/上下文。早期固定 1.5s 等待后直接退出存在未释放风险，已修正；退出时间实测单列，不承诺所有驱动都相同。
- 打包首试暴露全局 Anaconda PATH 中 ICU 78 与 Windows 系统 ICU 同名冲突。构建子进程限定 Python 与 Windows 路径，使用项目私有 PyInstaller 缓存重新分析；不修改系统 PATH、不安装或替换系统 DLL。
- MediaPipe 当前 wheel 的顶层导入需要 Matplotlib；即使应用不画统计图，也不能从包中排除此传递依赖。打包测试必须同时断言没有 pipeline_error、有同帧结果，不能仅看 GUI 进程退出码。
- 摄像头当前实际约 10Hz，与设备报告的 30FPS 不一致。单独采集仍约 9–10Hz；试请求 MJPG 后设备仍返回原格式且未提速。未修改系统曝光/隐私设置。下一步结合真实站位、光照、设备模式验证，暂不把 640×360 强制当作解决办法。
