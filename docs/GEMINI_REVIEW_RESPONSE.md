# 对 Gemini 首轮方案审查的处理

输入仅有用户粘贴的三张任务卡；Gemini 未读当前代码、未运行项目。卡片提到的“第二节六条轨迹”和“第四节全部诊断字段”全文未提供，因此不能声称已逐字覆盖那两节或达到 100% 代码覆盖率。

| 意见 | 结论 | 当前处理与理由 |
|---|---|---|
| 同帧、等比例像素/肩宽、world 坐标隔离 | 接受 | `tracking.py` 与同帧 `Tracker`；记录两模型相同时间戳；零骨段、分辨率采样测试 |
| Handedness 翻转不换角色；Pose 腕回退 | 接受 | 关联靠 Pose 腕与连续性为主，类别仅弱证据；施法角色锁定；交叉不确定则 UNKNOWN；日志明确 HAND_POSE / POSE_FALLBACK / UNKNOWN |
| 侧身尺度退化保护 | 接受并调整 | 肩宽低于绝对阈值或近期尺度约 45% 时暂停可靠特征，保留最近尺度/胸锚；这只能发现退化，不能准确测量身体转角 |
| 掌宽变大代表完全伸直 | 不采用 | 透视、靠近摄像头和手掌朝向都能改变掌宽；保留三维肘角与校准，失效时保持后衰减 |
| 八状态及合法 TRANSFER 优先级 | 接受 | A 的全部状态已有独立测试；图形测试也经过 TRANSFER/OVERDRIVE/恢复 |
| CAST 离胸 d>0.45 必定 TRANSFER | 调整 | 不能让任意离胸都无条件保留攻击；现有 CAST + 近期接近施法前臂才打开 650ms 窗口。原方案没有要求以新阈值覆盖产品规格 |
| 极限时手指可遮挡、整个支撑腕不能无限丢失 | 接受 | 可靠 Pose 腕可维持；Hand/Pose 腕都失去超过 300ms 退出。短遮挡不能创建新的极限状态 |
| 有序事件不随快照覆盖丢失、不重复 | 接受 | `EventJournal` 原子消费与去重；显式溢出错误、超龄计数。碎镜事件携带触发 RGB 帧但日志不保存 RGB |
| 丢手后外推到合掌而触发碎镜 | 不采用 | 只在重新看到有效双手并满足收缩速度、比例、距离时触发；丢手仅保留/关闭。新增“快速收至一半后丢手也不碎镜”的负样本 |
| 每帧重新 detect Qt FBO | 调整 | 每帧查询实际 FBO ID 与 DPI 像素尺寸；变化时重建外部引用，避免无必要包装对象。10 次缩放/全屏和非对称色标测试检查实际结果 |
| 推理固定 640×360 | 暂不强制 | 现有源 1280×720、模型内部裁剪，同帧串行；实测采集本身约 10Hz。降低输入分辨率可能损伤手部细节，需与真人输入做测量比较 |
| JSONL 诊断、p50/p95、resize 证据 | 接受 | 主动开启关键点/状态/控制/模型时间戳/分项耗时/数据年龄；不录原图。审查包只含构造图与非个人统计 |
| 关闭 1.5 秒与无残留 | 作为验证目标 | 修复直接退出时工作线程可能未结束的问题；最近实际退出时间见 VALIDATION，不冒充全设备保证 |
| 重建任务卡目录及 main 入口 | 不采用重建 | 保留现有代码；实际入口 `python -m mirror_moon --diagnostics`，核心无 Qt/MediaPipe 依赖的测试仍能独立运行 |
| 提供真人 G0 初测包 | 待用户完成 | 目前软件验证、模型/摄像头连通、构造轨迹与图形测试已做；用户本人动作与审美尚未进行。不能生成虚构真人结果 |
