## 5. 共用识别规则

### 5.1 坐标和身体尺度

输入图像保持未镜像坐标用于识别。镜像只在显示变换中统一处理，视频、关键点、特效一起变换。左右手用人体的解剖左右，不能从屏幕左右推断。

二维几何先换成等比例像素坐标 p=(x·W,y·H)，再除以平滑肩宽 s；不能直接在宽高分别归一化的 x、y 上计算欧氏角度。胸部锚点初值为肩中点沿躯干方向下移约 0.25s；髋部有效时用于确定方向，无效时使用画面向下。身体侧转导致肩宽过小时暂停更新尺度并提示重新站位。

位置、接近距离以肩宽为单位，手指开合以掌宽为单位。挥动开始时冻结该次动作的尺度基准，防止肩宽抖动制造假速度。

手部世界坐标的原点在各自手部中心，人体世界坐标的原点在髋部中心。两者不能直接相减，也不能用两只手各自的 world 坐标直接量两手间距。跨模型接近判定使用同一图像坐标，手内形态和人体肘角分别在各自模型内部计算。参见 [Hand Landmarker 输出](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python?authuser=01) 与 [Pose Landmarker 输出](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker?tab=Python)。

### 5.2 角色锁定

用手部腕点与同帧 Pose 左右腕点的距离、前一帧位置连续性和 handedness 共同配对。两只手仅两种排列即可比较，不必上复杂跟踪框架。分类左右只作为证据之一。

召唤成功后锁定召唤手与施法手，直到整次施法结束。短暂遮挡或交叉不允许交换角色。关联不确定时输出 UNKNOWN，不能把“没有看见”当成“张开”或“握拳”。

Pose 的 visibility/presence 可用于可靠性门控。HandLandmarker 不应被假定为每个关节都有同样有效的可见性分数；左右手类别分数也不是整只手的定位精度。手部可靠性还要检查尺度突变、骨段比例、越界、关联距离和数据年龄。

### 5.3 手形、时间和平滑

基础手形只有 OPEN、FIST、PINCH、OTHER、UNKNOWN。开掌与握拳结合手指关节角、指尖到掌心的归一化距离和多指一致性，不使用“指尖 y 小于指根 y”作为唯一规则。拇指参与辅助评分，避免因拇指遮挡而频繁失败。

Pinch 使用拇指尖—食指尖距离除以掌宽，进入/退出不同阈值；初值可用 0.25/0.40，待校准。掌心法线可辅助判断朝向，但不作为硬性、精确三维朝向证明。

状态持续时间使用单调时钟和时间戳，不按固定帧数计时。重复时间戳丢弃，回放倒带时重置追踪；长间隔不补造路径。关键点视觉锚点采用 One Euro 或时间一致的 EMA；动作判定使用较轻的平滑。速度估计用短时间窗拟合，不直接用重度平滑后的画面位置。

所有秒数、距离和速度阈值放在一处配置；保存校准版本和测试条件。滤波只能改善抖动，不能恢复不可观测的深度或长期消失的手。

## 6. 系统 A：星环术——保留原始大型法阵

### 6.1 普通循环

任意一只手握拳横在胸前，持续约 250ms，建立召唤。拳头接近胸部区域、前臂有向内横置趋势即可，允许宽容姿态，不要求肘角 90°。两手同时满足时按用户偏好与先后稳定证据决定角色，无法决定则显示提示。

大型法阵以胸部为中心建立在人体前方的视觉层。直径初值约 1.8–2.2 倍肩宽，并适配画面边缘；不会附着在召唤拳头上。待机保持低速反向双环、细符文和稀疏光点。

另一只手抬起张开，稳定约 100ms，进入持续释放。手臂弯曲时输出低强度、伸直时高强度，可以反复来回。强度归零只停止能量输出，法阵仍存在。施法手握拳约 100ms 或明确放下约 150ms，停止输出回到待机；这些是明确动作，不应被长期丢帧宽限掩盖。

### 6.2 朝前伸臂的强度估计

不能只根据屏幕上肩到腕的距离计算：手朝镜头伸出会发生透视缩短。基线使用 Pose 模型同一坐标系的三维肩 S、肘 E、腕 W，计算肘内角：

θ=acos(clamp(((S−E)·(W−E))/(|S−E|·|W−E|),−1,1))。

这里 180° 表示伸直。校准得到 θ_bent 与 θ_extended，u=clip((θ−θ_bent)/(θ_extended−θ_bent),0,1)，输出 I=u²(3−2u)。校准端点过近则拒绝该次校准。默认端点可从 75°、160° 起试，不当成人人适用的真值。

同时检查人体关键点可见性、骨段长度稳定性、腕点与手部的图像配对、伸臂序列连续性。肩腕距离/臂长比可作一致性检查，但它与肘角相关，不能伪装成一份独立的深度证据。

当深度估计短暂异常，最多保持最近可信强度约 150ms，随后在约 250ms 内缓降并提示调整站位；不从 2D 距离硬切到另一算法导致强度跳变。若正面动作长期不可用，先比较 Pose Lite/Full、摄像头构图与校准；仍失败须明确列为未通过的核心风险，不以“把向前改成向侧面”悄悄宣告完成。

### 6.3 握臂极限形态

仅在已召唤且正常施法的上下文中识别。召唤手离开胸前并朝施法前臂移动，打开约 650ms 的 TRANSFER 窗口。此窗口内法阵和输出保留，不能先执行普通取消召唤逻辑。

用召唤手腕/掌根到施法前臂线段的二维距离作为主证据。设施法肘 E、腕 W、召唤手腕 H：

t=((H−E)·(W−E))/|W−E|²；P=E+clip(t,0,1)(W−E)；d=|H−P|/s。

进入极限的候选条件：近期来自有效 CAST；召唤手有向前臂接近的轨迹；t 大致位于 0.15–0.85；d 小于约 0.16；施法手仍张开/抬起；接近关系稳定约 180ms。退出距离先取 0.24，形成滞回。接近后两手相对运动趋同可增加证据，但不要求每个条件在每帧都完美。

这些规则识别的是“符合握臂意图的姿态”，并非触碰传感器。单目中手在前臂前后掠过可能投影相同，应通过动作顺序和负样本验证减少误触，报告保留其限制。

抓住胳膊时手指经常不可见，不能要求持续检测完整握拳。可以在腕点和前臂仍可靠时保持极限；整个支撑手/对应腕点均消失时，只允许约 300ms 的短暂宽限，禁止无限锁住。暂时不允许凭丢失直接新进入极限。

极限动画约 350ms：法阵中心由胸部平滑迁移到施法掌前的视觉位置，半径增至普通的约 1.3–1.45 倍，插值重新定向时继承当前动画位置，避免跳变。保持施法方向的稳定性，优先限制旋转幅度。

退出规则完整定义：

- 支撑手回到胸前握拳：退出极限并迁回身体前方；施法手开则回 CAST，否则回 READY。
- 支撑手脱离且未回胸：进入约 650ms RETURN 窗口；回胸可恢复，超时渐退至 OFF。
- 施法手明确握拳或放下：立即停止攻击，允许短暂 RETURN 恢复胸前召唤，不能继续输出。
- 人物整体离开或长期失去追踪：按时限停止攻击、渐退法阵；重入须重新召唤。
- Esc、切系统、关闭程序始终拥有最高优先级。

### 6.4 状态表

| 状态 | 进入 | 保持与退出 |
|---|---|---|
| OFF | 默认、完全取消 | 有效胸前拳稳定后 SUMMONING |
| SUMMONING | 锁角色、法阵展开 | 成功后 READY；明确撤销则淡退 |
| READY | 召唤拳保持 | 开掌抬臂→CAST；有效松拳/离胸且非传递→FADING |
| CAST | 召唤有效＋施法开掌 | 收拳/放下→READY；支撑接近→TRANSFER |
| TRANSFER | 支撑手向施法臂运动 | 握臂证据→OVERDRIVE；回胸→CAST/READY；超时→FADING |
| OVERDRIVE | 握臂证据成立 | 允许短遮挡；脱离或停止施法→RETURN |
| RETURN | 退出极限、等待回胸 | 回胸→CAST/READY；超时→FADING |
| FADING | 本轮结束 | 停攻击、衰减音效、释放角色，再到 OFF |

跟踪健康度作为独立输入，不给每个状态复制一套 LOST 状态。优先级：显式取消/系统切换 → 数据时效与安全停止 → 明确停止施法 → 合法 TRANSFER/OVERDRIVE/RETURN → 普通召唤维持 → 新动作。须用边界测试防止“离胸”在传递前吞掉极限入口。

### 6.5 大法阵的空间表现和遮挡

这是固定视角的 2.5D 合成，不承诺真实三维平面与手臂永不相交。单一人物分割只知道人/背景，不能自动知道哪条手臂位于法阵前后。

法阵保持身体锚定的大外环，中心和施法手通过区使用稀疏符文、半透明能量和渐变开口。前臂附近可以采用软边局部通道，将“穿过圆盘”设计成“能量通过阵门”。脸部区域限制辉光和纹样密度，确保能看见人的表演。

若局部遮挡确有收益，再将 Pose 前臂胶囊区域、手部轮廓与同帧人物 mask 相交，选择性重绘手/臂。胶囊是近似，不能凭空画出背景皮肤；识别不可靠时退回透明通道，不残留错误遮挡洞。主阵不因整个人物 mask 被整体盖到人体后面。

朝镜头释放时采用径向扩张、环形推进与轻度透镜扭曲，不能把很短的屏幕前臂方向放大成一束乱甩的横向激光。方向投影过小时沿最近可信方向渐变至正面表现，不计算不稳定的 atan2。

### 6.6 两种元素的质变

| 元素 | 普通释放 | 极限形态 | 收招 |
|---|---|---|---|
| 月华 | 双螺旋细流汇入稳定能量通道；伸臂改变流速与通道开合 | 身体大阵迁往掌前，拆成三层轴向阵列；中心聚束，周期性推出空间冲击环并扭曲背景 | 阵列合回单环，余辉沿符文回收 |
| 雷霆 | 间歇细电弧沿场线游走，有有界随机分叉 | 多个固定环上节点组织成电弧网络，轮流向中心坍缩后脉冲放电 | 电弧断开、节点依次熄灭 |

极限“质变”由拓扑、节奏和空间组织共同体现，不能只改颜色、半径和粒子数。所有随机效果可固定 seed，便于回放比较；震屏与闪光默认克制，可关闭。

## 7. 系统 B：月刃术——拔刀断月

这套系统不需要胸前召唤拳，另一只手也不承担必需动作。

动作：将施法手收至对侧肩前短暂停留，出现细月牙蓄势提示；向身体外侧快速横挥或斜挥，形成一次月刃；完成后在外侧可短暂停顿并反向挥出第二斩。

状态：IDLE → ARMED → SWING → EMIT → RECOVERY。只有 ARMED 后才判断斩击。初值：蓄势稳定 150ms，动作窗口 120–650ms，位移至少 0.65s，短窗速度峰值至少 2.5 肩宽/秒，净位移/路径长度至少 0.65，释放后至少 250ms 恢复并重新准备。全部为待测试初值。

轨迹取身体相对的腕/掌中心，减去胸部平移，避免整个人横移触发。以时间戳估计速度，窗口约 80–120ms。明显跟踪跳点、跨越长缺帧、出画后重新出现，不构成一次高速斩击。达到动作成立条件即发事件，不等待手完全停住才显示刀光。

强度采用经校准的速度分位值与有效跨度组合，例如速度权重 0.7、跨度权重 0.3，再饱和映射。达到舒适中速即可接近满威力，避免诱导用户越甩越用力。

视觉分为手边短尾迹、离手飞出的月牙实体、随后消失的空间细裂缝。弧线来自实际路径的轻度拟合，位置与方向跟动作一致；不是每次播放同一张动画。主要刀光持续约 180–300ms，细裂缝约 400–700ms。

修正旧方案的几何漏洞：纯水平正反挥只能形成平行或重叠斩痕，不天然构成十字。若约 800ms 内完成第二斩，且两条斩击线在舞台内相交、夹角约 35°–145°，才出现十字裂空。平行反斩生成双月连斩。第二斩同样需要新的有效轨迹和最短恢复，不从手腕噪声自动补发。

普通抬手、整理头发、挥手打招呼、转身与操作鼠标均为必测负样本。先完成规则与时序识别；只有负样本仍无法分离时才考虑 DTW，不在首版训练 CNN/Transformer。

## 8. 系统 C：镜界术——万象折镜

双手在胸前附近张开，间距约 0.25–0.5 肩宽并停留约 200ms，出现一条银色镜缝；两手向两侧拉开超过约 0.65 肩宽，镜面展开。两掌略朝摄像头便于追踪，不强制掌心相对导致手呈侧面难以识别。

镜面中心取双手中点，宽度由双手距离控制，高度采用固定比例并平滑；两手高度差控制画面内倾斜，夹角限幅。单目可靠支持的是二维平移、缩放和画面内旋转，不伪装完整六自由度操纵。

镜面内部必须采样真实摄像头纹理：基础模式镜像、局部波纹和轻色差；显示与身体关联的实时影像。它不是空心护盾，也不声称还原现实中另一面镜子的真实视角。

拉大并保持约 600ms，镜边出现“折镜准备”提示；再同步平移镜面约 0.35 肩宽，进入六分镜折叠。展开幅度控制分区张力，保持形态让用户容易表演。首版万花筒从同一原始摄像头纹理采样，避免递归抓屏导致无界反馈。

镜面完整形成至少约 350ms 后，双手快速向内合拢才触发破碎：间距收缩速度、总收缩比例、最小间距共同判定。缓慢收拢对应平静收镜，不破碎。快速合拢前的接近轨迹已成立时，允许最多约 150ms 的最后遮挡宽限；单纯丢手不当成合掌。

碎裂瞬间冻结镜内纹理，把镜面切成预生成三角碎片，沿不同方向离散，约 500–900ms 淡出。碎片保留镜像片段，不只是撒一堆发光三角形。无需实现刚体物理。

单手短丢约 200ms 时保持上一尺寸且不接受新动作；更久则逐渐消散。截图、暂停、切系统不会意外触发碎裂。

状态：IDLE → SEED → OPENING → MANIPULATING → FOLDING（高阶）→ SHATTER 或 CLOSING → IDLE。基础操纵与明确收镜必须先于高阶花样完成。

## 9. 系统 D：摘影术——月下分身（扩展设计）

用户肩旁出现可抓取的影子标记；拇指食指捏合抓住，向外拖动约 0.5 肩宽，拉出一层人物影像；松开后播放抓取前约 1.5 秒的短动作片段，播放一次并消散。这样区别于一直尾随用户的视频拖影。

先做单分身。人物 mask 与视频来自同一帧，每个历史样本携带时间戳、肩中点、人物尺度和有效性。回放把历史人物锚点映射到释放位置，限制平移和缩放，避免用户走动后影子随机漂移。颜色用银灰/蓝灰、低透明度和边缘光，保留“过去动作”的辨识。

缓存采用 RGB8 + mask8 或 RGBA8，先以 320×180、15fps、2 秒环形缓冲为上限。纯像素容量为 320×180×4×30=6,912,000 字节，约 6.6MiB；这不包含对象、复制和 GPU 开销。640×360 同配置约 26.4MiB。不得缓存整段高分辨率 float32 视频。

保持一段最多 2 秒历史和一段最多 1.5 秒的活动快照，总预算明确计数；同时存在一个分身。后续三分身共用同一快照和不同播放时钟，不复制三份完整历史。用时间戳选择帧，不假定推理频率固定。

优先复用 Pose 已有的可选人物分割输出。质量不够再评估一个轻量分割模型，不默认同时常驻三个重模型。人物分割差时显示无法抽影的反馈，不拿矩形视频块当人物分身。

该方案没有还原身体背面、三维移动或真实空间克隆；这些都不属于本项目承诺。

## 10. 统一视觉与声音

主题为“月相、镜面、星轨”。主色月银与深靛，雷霆使用少量暖金。法阵遵循一组可辨识几何：外部刻度环、中部符文带、内部能量结构；避免无限增加同心圆和通用六芒星拼贴。

每种效果都分准备、成立、控制、退出四段。准备提示低亮度，成立给予清晰瞬态，持续阶段避免闪烁，退出收束剩余粒子与声音。动作成立时先给轻量反馈，完整法阵展开可以稍慢；动画时长不等于识别延迟。

人物脸部和动作优先可读。Bloom 从半分辨率缓冲起步，用亮度阈值限制范围；不能把整个人照成白块。扭曲只影响效果附近，不全屏持续晃动。粒子使用实例绘制与数量上限，核心轮廓在轻量模式下仍然完整。

声音事件与状态变化绑定：召唤一下、持续环路、极限进入一下、结束释放。不能每帧重复启动音效。持续音量按强度平滑，失去追踪、切系统、关闭窗口均渐停。无音频设备或素材缺失时应用继续运行并给一次明确提示。

首版素材优先程序生成法阵、原创简单音效或许可清晰的素材。版权角色纹章、电影原声和来源不明贴图不作为默认资源。

## 11. 技术架构与性能设计

### 11.1 数据流水线

初版用三个执行职责：摄像头采集线程、推理/动作处理线程、Qt 主线程。Qt 主线程负责 UI 和 OpenGL 绘制，初版不把 OpenGL 随意移到后台。

采集持续读取，只保存最新待处理帧（容量 1，替换旧帧）。推理线程取得一个帧后，使用 Tasks 的 VIDEO 模式依次运行 Hands、Pose，二者共享严格递增的时间戳，计算动作后发布一个不可变 ScenePacket。VIDEO 指 API 的带时间戳模式，并不禁止输入来自摄像头。该选择便于同帧关联和确定性回放。

渲染显示该 ScenePacket 对应的视频帧和关键点，效果动画可按 60Hz 更新，识别按实际可达频率更新。不要用最新视频搭配任意旧关键点。先测量同帧串行链路，再考虑并行两个模型；并行时仍按 frame_id 汇合，有明确超时和缺失标记。

MediaPipe LIVE_STREAM 会在忙碌时丢弃输入，不能假设每次提交都有回调。若后期改用它，需独立处理乱序、双模型不同步和结果过期。官方说明见 [HandLandmarker API](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/HandLandmarker)。

仅当同帧基线的延迟实测明显不足，才评估最新画面配短时预测的方式，并把 mask 时效、误差上限和失效策略作为整项功能测试。不能为了 FPS 数字牺牲人物和法阵的位置关系。

### 11.2 最小接口

| 对象 | 关键字段/职责 |
|---|---|
| FramePacket | frame_id、采集返回时刻、源视频时刻、宽高、只读 RGB 帧、镜像变换信息 |
| TrackingFrame | 同帧双手/人体坐标、关联角色、可选 mask、每个来源的时间戳、有效性及原因 |
| ActionFeatures | 手形、身体相对位置、肘角/强度、轨迹质量、前臂接近证据 |
| SpellState | 系统、元素、状态、进入时刻、手角色、控制值、质量状态 |
| EffectEvent | 唯一 event_id、类型、源 frame_id、发生时间、参数、随机 seed |
| ScenePacket | 与结果对应的图像、持续控制值、待展示事件、锚点与健康度 |

纯 Python 的 update(tracking, controls, now) 输出状态与事件，不依赖摄像头、Qt 或 GPU。渲染器只读状态和事件，不修改业务状态。音效按 event_id 去重。

“最新值可覆盖”仅适用于连续状态，不适用于瞬发月刃、碎镜和音效事件。事件用有界序号队列加消费确认；丢弃旧 ScenePacket 时不能静默丢失尚未消费的瞬发事件。队列溢出需记录，过时事件按显式策略丢弃，不能无限补播。

线程间明确图像所有权：生产者不得继续修改已发布的 ndarray。Qt 信号只通知“有新快照”，不要把每帧大数组排进无界 UI 消息队列。停止时通知工作线程、关闭模型、释放摄像头并有限等待退出。

### 11.3 模块组织

建议 src/mirror_moon 下分 capture、tracking、interaction、render、ui、audio、diagnostics；tests 中放状态机和几何测试；assets 放着色器与素材；tools 放模型准备和打包入口。只建立真实需求对应的模块，不先造通用插件市场、ECS、网络协议或复杂依赖注入框架。

仓库长期文档保持少而准确：docs/SPEC.md（本方案）、docs/DECISIONS.md（重要变更及原因）、docs/VALIDATION.md（实际证据和待测项）、docs/HANDOFF.md（当前状态与下一步）。第三方代码与素材使用 THIRD_PARTY_NOTICES.md。

### 11.4 OpenGL 集成

首选 OpenGL 3.3 Core 作为目标，进入原型验证实际显卡/驱动是否支持。QOpenGLWidget 创建并拥有上下文，在 initializeGL 中附着 ModernGL；在 paintGL 中绘制。不能在未激活上下文时创建 GPU 对象。

Qt 的绘制目标是自己的 framebuffer，不能假设是 0 或任意持久 ctx.screen。需要在 Qt 当前 framebuffer 已绑定时检测/绑定正确目标，并处理 resize、DPI、上下文重建与资源释放。Qt 文档明确指出默认 framebuffer 会在 resize 时变化：[QOpenGLWidget](https://doc.qt.io/qt-6/qopenglwidget.html)。ModernGL 提供上下文与 framebuffer 操作：[Context](https://moderngl.readthedocs.io/en/latest/reference/context.html)。

按实际 framebuffer 像素尺寸设置 viewport；窗口逻辑坐标与 devicePixelRatio 分开。统一色彩通道和纹理 Y 翻转，先用非对称测试图确认方向。纹理和粒子缓冲预分配，避免每帧重新编译 shader 或创建纹理。

Bloom 使用独立低分辨率亮部缓冲；透明合成选定预乘或非预乘 alpha 后全链路一致。RGB 摄像头纹理只做必要上传，避免正常渲染路径反复 GPU→CPU 读回。

### 11.5 明确的降级路线

同一 GPU 渲染器内按顺序降低 Bloom 分辨率、粒子上限、扭曲采样和输入分辨率。降低分割频率只用于允许滞后的装饰效果，不将旧 mask 硬贴到新视频；摘影录制仍保持图像与 mask 对齐。

若 OpenGL 完全不可用，唯一备用为 PySide6 的 QWidget/QPainter＋NumPy/OpenCV 的简化二维合成，复用相同状态机与接口。该模式明确显示“兼容画质”，保证基础法阵、斩击、镜面功能，减少高阶后处理。它通过功能验证不代表高画质验收通过。不再引入 Electron/Unity 作为第二工程。

### 11.6 环境与打包

选择 Python 3.12 是保守的项目基线，而不是声称其它版本都不支持。Google 当前设置页列有 Windows 和 Python 支持范围；最终取决于实际 wheel 和依赖组合：[Python setup](https://developers.google.com/edge/mediapipe/solutions/setup_python)。

使用项目虚拟环境，导入、模型加载、摄像头、音频、OpenGL 小样通过后锁定依赖。避免同时安装多个冲突的 OpenCV wheel；由依赖解析和实际导入决定所需的唯一提供者。模型记录官方来源、版本和 SHA-256；开发时按需下载，最终包携带已验证的模型，运行不依赖临时联网下载。

先打包 onedir，确认 Qt 插件、模型、字体、shader、音频路径；再决定是否需要 onefile。检查中文与空格路径、普通用户权限、非开发目录启动。日志/配置写用户可写位置，不写安装目录；缺模型、占用摄像头和不支持 OpenGL 都给可读提示。

## 13. 验收与证据

### 13.1 先证明最难的部分

G0 不是只验证摄像头能打开。需验证：双手与 Pose 同帧；正面肘角随弯伸可用；从胸前转到握臂时状态不断；法阵胸部→掌部迁移稳定；Qt/ModernGL 在窗口缩放后仍正确；数据不会持续排队变旧。

若某项未通过，记录输入、日志、截图/录像和原因，集中修复该项。真人尚未执行的部分标记待测，同时继续可独立完成的状态机、回放和界面工作。不能把模拟骨架测试等同于真人识别成功。

### 13.2 自动化测试重点

- A：强度下降与停止攻击不删除已召唤法阵；合法 TRANSFER 优先于离胸取消；极限进入/退出与回胸恢复；丢失不能无限保持攻击；左右手角色不被单帧分类颠倒。
- B：同一动作只发一次；静止抖动、人体横移、时间戳异常、长缺帧和重新入画不触发；平行双斩不变成十字。
- C：未展开不能碎裂；慢合拢为关闭、快合拢才碎裂；单手丢失不是拍掌；中性恢复不立即重触发。
- 共用：镜像不改变解剖角色；不同分辨率/等效时间采样产生一致状态；零长度骨段不 NaN；模式切换清理；事件不重复不静默丢失；关闭释放资源；历史缓存有上限。

状态机测试使用带时间戳的构造轨迹与已标注实际回放；真实录像与关键点记录分开存储，默认不上传个人录像到公开仓库。几何测试和状态测试不依赖真实摄像头和 GPU。

### 13.3 真人测试与目标

建议至少 3 名参与者，在正常光照条件下每个关键动作做 10 次；左右手召唤均覆盖。若实际只测一人，应如实记录，不写成适用于所有人。另留一名参与者或一组场景不参与调参，避免只适配演示者。

| 指标 | 初始验收目标与定义 |
|---|---|
| 关键动作成功率 | 正常条件每个关键动作至少 27/30；超时、错角色、需重做均记失败，并展示分动作原始计数 |
| 误触发 | 明确负样本 5 分钟内意外事件不超过 1 次；按系统记录，不使用分母不明的“误触率5%” |
| 普通循环稳定性 | 待机、增强、减弱、停止、再次施法可连续完成；不因强度零删除主阵 |
| 握臂 | 转移、保持、回胸、放手、遮挡分别测试，不只展示一次成功镜头 |
| 渲染 | 目标标准画质 720p 平均至少 30FPS，并报告 p95 帧时间；60FPS 为争取项 |
| 跟踪 | 目标有效结果至少 20Hz；不足时先确认是否仍满足动作采样与延迟，不能用渲染FPS替代 |
| 软件数据年龄 | 目标采集返回至对应绘制提交 p95≤150ms；这不含摄像头曝光/缓冲和显示器全部延迟 |
| 端到端体验 | 有连续控制和离散触发两组测量；连续可见响应先争取≤200ms，准备保持时间单独报告 |
| 稳定性 | 连续运行30分钟、切系统与开关窗口重复测试；预热后内存无持续增长、无未释放摄像头 |
| 包体可用性 | 非开发目录启动；无网、缺模型、摄像头被占用、设备拔插均有可理解行为 |

这些都是待验证目标，不是本方案已达成的结果。深度估计抖动、校准时长、兼容画质表现需另附主观与客观记录。

用手机高帧率录像同时拍到真实手和显示器，估算真实动作到屏幕反应。区分用户开始准备、规则满足时刻和首个可见反馈；不能要求持续 250ms 的召唤动作在动作开始后 100ms 已正式成立。软件计时只能说明管线局部耗时，不能冒充完整摄像头到屏幕延迟。

为课程增加一个小而真实的对比实验：原始关键点/固定EMA/One Euro 的静止抖动与运动滞后；单阈值/时序+滞回的负样本误触；必要时比较 Pose Lite/Full。记录环境和样本，展示取舍，无需训练新模型。
